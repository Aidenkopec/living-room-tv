# TV change log

Every change made to the living room TV (Hisense 55A51HUA), in order, with the exact command that undoes it.

## How to read this

- **Remove** means the app is deleted. To undo, reinstall it from the Play Store.
- **Turn off** means a built-in app is hidden and stopped. The original stays on the TV, so it can be turned back on with one command.
- Commands start with `adb -s $TV`, which means "send this to the TV". `$TV` stands for the TV's address on your home network (for example `<address>:5555`); the scripts read it from the git-ignored `.tv` file. The Mac must be connected first (see the README). Each row has its date; times of day are left out. Commit IDs in the Undo column refer to the project's history before it was published.
- **Checks** are the four tests run after every change: the home screen opens, HDMI 1 switches, Cast and AirPlay are offered on Wi-Fi, and a YouTube video plays (`scripts/check-tv.sh`). The script prints five lines because Cast and AirPlay are counted separately, hence "5/5".
- **From Phase 2 (#18 on)** the script has a sixth line, "Google home opens directly": the way our home screen's "Google TV home" entry opens Google's screen. So those rows say "6/6". Once our app catches the Home button (#21), "Home screen opens" means *our* screen opens.
- The check script uses the TV for about a minute: it plays a YouTube clip out loud at the current volume, and switching to HDMI 1 can wake the PlayStation 5. Run it when the room is free.
- Commands are written for the Mac's Terminal (zsh). Paste them as they are, quotes included.

## Ways back

From smallest to biggest:

1. **Undo one change:** run the command in that row's "Undo" column.
   - **Put an earlier Living Room build back.** The TV won't install an older version number over a newer one, so the old code is rebuilt with a *higher* number. Pick the commit from the row you're undoing, and a number one above the build on the TV (`adb -s $TV shell dumpsys package tv.livingroom.home | grep versionCode`). Then:
     ```
     git worktree add --detach /tmp/lr-old <commit>
     sed -i '' 's/versionCode = [0-9]*/versionCode = <number>/' /tmp/lr-old/launcher/app/build.gradle.kts
     cp launcher/local.properties /tmp/lr-old/launcher/
     (cd /tmp/lr-old/launcher && JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :app:assembleRelease)
     adb -s $TV install -r /tmp/lr-old/launcher/app/build/outputs/apk/release/app-release.apk
     git worktree remove --force /tmp/lr-old
     ```
     The Home takeover and usage access stay on. The next build from the main code must then use a number above that one. (The rebuild was tried on the Mac on 2026-10-19 and works; the install step is the usual one, not tried with an old build.)
   - **If you remove Living Room instead** (`adb -s $TV uninstall tv.livingroom.home`), Android also drops its Home-button service, usage access and notification access, and the saved Continue watching shows. The TV then goes back to Google's screensaver by itself (Android's rule; not tried), but keeps the 2-hour sleep (#54). After installing it again, run #21's two commands, #27's command, #37's command and #53's command again.
2. **Undo everything:** `scripts/restore-tv.sh` shows what it would put back; `scripts/restore-tv.sh --apply` does it.
   - **After a Hisense or Google update**, run `scripts/restore-tv.sh` (it only looks) as a check-up. Since #78 it prints **22 "WOULD" lines and 1 "BY HAND" line**: the 15 from Phase 1, plus 5 for Living Room (its Home-button service, accessibility back off, its usage access, its notification access, uninstall), plus 2 for its screensaver (Google's screensaver back, #53; the 20-minute sleep back, #54), plus 1 for the time zone (Edmonton back, #78), minus Google Assistant, which Hisense turns back on (see "Still open" under the milestone 1 done check). Fewer lines means something switched back on or was reinstalled; turn it off again with that row's command.
   - **If the TV is laggy after a Hisense system update**, its ready-made app code was thrown away (#81). Check with `adb -s $TV shell dumpsys package dexopt | grep -c status=verify` (about 80 is normal; about 126 right after an update). The fix: `adb -s $TV shell cmd package bg-dexopt-job` (about 20 minutes; the TV can be used meanwhile, but don't put it in standby), then restart the TV so the running apps load it.
3. **No Mac, Home button back to Google's:** **Living Room → long-press any tile → Home screen settings → Switch back to Google's home screen** (from #45; it asks first). To come back, the same screen's **Use Living Room for Home again**, then Living Room → Enable → OK (#47). Or Settings → System → Accessibility → under **Services**, Living Room → off. (The Accessibility screen and the Living Room entry were checked on the TV; the menu path to it is Google TV's usual one, not walked by hand.) (Settings → Apps → Living Room → **Force stop** does the same: Android switches off a force-stopped app's accessibility service.) To remove Living Room completely: Settings → Apps → Living Room → Uninstall. Living Room's usage access (#27): Settings → Apps → Special app access → Usage access → Living Room → off; the top area then just stops saying when apps were last opened. Living Room's notification access (#37): Settings → Apps → Special app access → **Notification access** → Living Room → off; shows already on the Continue watching row stay, but no new ones are added. Living Room's screensaver (#53): the TV's menus have no screensaver picker (System → Ambient mode only offers "Start now" and Google's own settings), so without the Mac the way back to Google's screensaver is removing Living Room (above). The 2-hour sleep (#54) has no menu setting either; `scripts/restore-tv.sh` puts it back.
4. **No Mac:** turn a built-in app back on from the TV: **Settings → Apps → See all apps → Show system apps**, pick the app, then **Enable**. (Standard Google TV path; not tried on this TV.) Removed apps: search for them in the Play Store.
5. **Last resort:** factory reset (below).

## Getting ADB back after a restart

Checked on the TV 2026-10-19. This TV has **no separate "network debugging" switch**, only **USB debugging** (on, and saved). The network port itself comes from `service.adb.tcp.port=5555`, a setting that is **not** saved across restarts. Since the README's first-time setup never needed an extra step to open the port, Hisense most likely sets it again at start-up while USB debugging is on, but this hasn't been tested (Phase 1 avoided restarting the TV).

Also: Android forgets an "Always allow" computer that hasn't connected for about 7 days, so expect the TV to ask again after a long gap.

If `adb connect $TV` fails after a restart:

1. On the TV: **Settings → System → Developer options → USB debugging**. Turn it off, then on again.
2. On the Mac: `adb connect $TV`.
3. If the TV asks, tick **Always allow from this computer** and select **Allow**.
4. If it still can't connect, the port didn't come back. The menus still work for everything (see "No Mac" above).

**Tried 2026-10-21:** after a restart the port came back by itself (USB debugging on), so the step above wasn't needed.

**Can't reach the TV from VS Code** (seen 2026-10-21): when Claude Code runs in VS Code's terminal, everything on the home network except the router answers "No route to host", even with VS Code allowed Local Network access. So it looks as if the TV is off the network when it isn't. Homebrew's `adb` and Python can't get through from the Terminal app either, but the Mac's own `ping` and `nc` can. Two ways round it:

1. Run Claude Code from the **Terminal** app instead (`cd` into the repo, then `claude --resume`).
2. Or a relay in a Terminal window, made from the Mac's own `nc`, then `adb connect 127.0.0.1:15555` (the TV then shows up as `127.0.0.1:15555`; scripts take `TV=127.0.0.1:15555`):
   `while true; do rm -f /tmp/relay; mkfifo /tmp/relay; /usr/bin/nc -l 127.0.0.1 15555 < /tmp/relay | /usr/bin/nc <tv-address> 5555 > /tmp/relay; done`

If Developer options is missing, it was turned off: **Settings → System → About**, select **Android TV OS build** 7 times, then do the steps above.

## Last resort: factory reset

A factory reset erases everything: sign-ins, installed apps and settings. You'd sign in to Google and each streaming app again. Use it only if nothing above works.

**With the menus (preferred):** **Settings → System → About → Reset** (path checked on this TV 2026-10-19), then choose factory reset and confirm.

**Without the menus (TV frozen or menus unreachable):** Hisense doesn't publish a button-only reset for this model (55A51HUA, likely the Q6N series). As of 2026-10-19 their support sites had no such page. The method below is the usual one for Android/Google TVs, described by third-party guides. It is **not confirmed for this model**, so try the menu way first.

1. Unplug the TV from the wall.
2. Find the TV's own power button (on the TV itself, usually underneath the middle of the bottom edge, not on the remote).
3. Hold that button down and plug the TV back in. Keep holding for about 30 seconds (some models need up to 60), until a text "Android Recovery" menu appears.
4. In that menu, a short press moves down and a long press selects. Choose **Wipe data/factory reset**, confirm, then choose **Reboot system now**.
5. If the menu never appears, ask Hisense support (Canada) for this model's exact method.

Sources: [HiRemote: Factory reset a Hisense TV without the remote](https://hiremote.app/blog/factory-reset-hisense-tv-without-remote), [SlashGear: How to reset a Hisense TV](https://www.slashgear.com/1786224/how-to-reset-hisense-tv/). Both are third-party, not Hisense.
